# SE Workflow｜同学交接

本版串联课堂作业 1、2、3。讨论记录先提炼出带原文证据的要点，负责人处理分歧并确认共同理解后，转入产品想法。完整流程依次生成需求规格、设计规格、任务分解与编排、设计回填和测试方案。运行记录展示各阶段的开始、完成及失败，执行页提供人工补充、异常处理和交付确认。

## 先打开看一遍

1. 完整解压。电脑需要 Node.js 22 或更新版本。
2. Windows 上双击 `Start.cmd`，或在项目目录运行 `npm start` 后访问 [工作台](http://127.0.0.1:8765/)。
3. 点击页面右上角的「DeepSeek 密钥」，输入自己的 API 密钥。可以先展开「讨论提炼与人工确认」填入讨论，也可以在左侧直接选择案例。点击「运行完整流程」后，产物会逐阶段出现。密钥仅在当前页面使用，刷新后需重新输入。

包里已带可运行的前端文件，首次启动无需安装依赖。在线生成需要能访问 DeepSeek API 和可用的 API 密钥。若有之前从工作台导出的 DeepSeek JSON，可以通过「导入 DeepSeek 结果 JSON」离线回放。

## 分工时从哪里改

| 要改的内容 | 修改位置 |
| --- | --- |
| 页面布局、样式、按钮及导出 | `index.html`、`style.css`、`app.mjs` |
| 演示想法与 Design Spec | `examples.mjs` |
| PM Agent 提示词、DeepSeek 请求、错误处理 | `server.mjs` |
| 任务校验、交付物依赖、测试前置、执行批次 | `workflow.mjs` |
| 需求、设计、任务和测试方案的编号关联 | `pipeline.mjs` |
| 讨论证据校验、任务状态与前置完成检查 | `interaction.mjs` |
| 可观测记录、讨论确认与执行交互界面 | `observability.mjs` |
| 前端构建和 Windows 程序打包 | `build.mjs` |

`app.browser.js` 是构建生成的浏览器脚本。改动 `app.mjs`、`examples.mjs` 或 `workflow.mjs` 后，先在项目目录运行一次 `npm ci`，再运行 `npm run build` 并刷新页面。改了 `server.mjs` 或编排逻辑后，重启服务再验证。

## 构建可双击运行的程序

在 Windows x64 上使用 Node.js 26 或更新版本。运行 `npm ci` 和 `npm run build:windows` 后，生成文件是 `dist/SE-Workflow-Classroom.exe`。

## 改完后验证

先跑「旅游行程分配」，点每日时长限制对应的需求，检查关联的开发和测试任务。再换「校园活动报名」，点击一条依赖并查看前置交付物，将并行上限改为 1，确认每批只排一项。最后导出 JSON，再导入一次检查能否回放。详细上台顺序见《课堂展示与使用说明》。

编排器检查任务结构与先后关系。验收标准是否符合业务需要，仍要对照原始规格核对。压缩包未附带 API 密钥。

## 第三次作业的展示

每项前端或后端实现交付后进入单元测试，消费该交付物的任务需要等待单元测试。实现之间存在交接时，编排器增加集成测试并验证交接。全部工作就绪后执行端到端验收。测试用例的需求、设计和任务编号由工作台预先关联。

测试失败后，负责人根据证据选定有缺陷的实现。执行页会预览回退范围，将目标实现标记为待修复，让依赖它的任务按前置关系重新执行，并保留所有历史记录。这项操作记录返工与重验状态，代码修复和交付由任务负责人执行。

打开《第三次作业展示说明.md》，按讨论主线、连续产物、执行交互三部分展示。通过「导出 JSON」可以保存完整产物、讨论证据、运行日志及任务交互状态并恢复。通过「导出 task.md」交付工种级任务卡。任务执行由负责人或外部 Agent 完成后在页面提交进度与交付信息，记录会区分模型生成事件与人工确认事件。
